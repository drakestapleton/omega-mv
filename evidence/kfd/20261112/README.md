# KFD compiler CPU evidence

The language contract is in `docs/one_layer/OMEGESE.md`, “KFD device words”.
`compiler-before.sha256` records the incoming compiler. `compiler-after.sha256`
records the exercised compiler, its Omega source, and the installed Linux UAPI
header. `requests.txt` is generated by the independent C header oracle;
`results.json` is generated by the KFD gate. `disassembly/` contains the actual
AArch64 and x86linux code disassembled by LLVM, not a source-level substitute.
`oracle-versions.txt` records the independent test instruments. C and Python are
only measurement/oracle code here; neither is a production KFD implementation.

## Commands and outcomes

All builds and gates used this CPU-only prefix on spark-b87b:

```
flock ~/handoffs/hive/queen/pool-14.lock nice -n 10 taskset -c 14
```

The final KFD and canonical seeded-compiler run is `qualification-4.log`:

```
sh seed/omega-from-seed.sh &&
python3 tests/kfd/check.py --record-history &&
PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 tests/gates/run.sh seed
```

The conjunction exited 0: each constituent exited 0. The seed runner includes
`seed/host/check.sh` (the current compiler, host, IRQ and crypto gates) and the
full `seed/omc/gate5.sh` self-host/corpus/mutation qualification. Exact case
results, compiler fixpoint hashes and negative-control exits are in that log.
The KFD gate's `killed-*` cases deliberately compile/run with a weakened compiler:
the formerly refused input succeeds, demonstrating that its refusal check would
fail against the mutant. The production compiler refuses that same input first.

`compatibility.log` records these additional existing CPU gate invocations,
with one `GATE_EXIT` line per completed invocation:

```
make PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 test-compiler-quick
make PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 test-numeric-cpu
make PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 test-realize
```

Earlier reseed, cpu and qualification logs preserve unsuccessful development
attempts rather than overwriting them. They are not passing receipts. Repairs
included the bootstrap compiler's expression/register constraints, preserving
the existing x86 mmap mutation seam, and correcting test-oracle assumptions:
QEMU reports ENOTTY for untranslated KFD ioctls before fd lookup, OM-1's generic
function refusal masked the intended OM-2 compiler mutant, and Omega's output
word is `write`, not `fwrite`. The final run exercises the repaired cases.

## Boundaries

No AMD device was opened or used. Every device/request row is NOT_RUN.
The successful CPU mmap/reservation tests and syscall-boundary ptrace oracle
are not successful GPU allocation, queue dispatch, interrupt delivery or
hardware qualification. Successful DRM ACQUIRE_VM is NOT_RUN. The installed
header supplies the optional SCRATCH and RUNTIME request shapes; it does not
prove that an eventual remote MI300X kernel implements them.

The existing seed gate explicitly reports missing sibling-unit coverage for
omega-mcp, cortex and interplane-forge, and a non-vendored Wycheproof corpus.
Those rows remain NOT_RUN. Physics-dependent, other sibling-dependent and
hardware suites were not claimed as run. No GPU, sudo, service change, model
change, push, merge or deployment was performed. Independent final-head review,
Radicle landing and the omega-harness pin/guide synchronization belong to the
integration lane.

## Paths beyond the initial compiler/doc/test claim

- `seed/omc/gate18.sh`: the old manually typed keyword count rejected a generated
  table extension; it now derives the count while retaining exact generated
  table equality and the existing keyword-specific assertions.
- `seed/omc/size-history.tsv`: the repository's gate5 requires an append-only
  measured row for the exact rebuilt compiler. The KFD measurement instrument
  generates it from the compiler/source only after its checks pass.
- `CONTRIBUTORS.md`: the repository instructions require model attribution.
- This evidence directory: explicitly requested by the assignment; new files
  only, with no modification to older evidence.

No production dependency was introduced. The existing mapping-handle capacity
was not expanded or presented as a new KFD limit. The caller-approved whole-
reservation `mapbind` route supplies same-VA mappings without an overlapping
submapping interface. Existing `mapaddr` exposes the checked base for GPU data;
it does not permit injecting an unchecked address into a KFD ioctl header.
