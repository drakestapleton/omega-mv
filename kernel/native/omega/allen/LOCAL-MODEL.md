# Local Omega model experiment

This opt-in application links Allen's existing conversation lifecycle to the
Omega LLM CPU implementation from `aien-dev/aien-train`. The checkpoint,
tokenizer, attention, sampling and arithmetic run inside the firmware guest.
The guest contains no Linux runtime and makes no network inference requests.
It does not replace the default Allen firmware or change the frozen C kernel.

This is a **firmware-hosted application under x86-64 emulation**. UEFI Boot
Services remain active. It is not the standalone Aienux kernel, an ARM64
firmware port, native Apple Silicon execution, or hardware qualification.

Observed November 6, 2026 on an M2 MacBook Air: the Astra checkpoint produced
` The kitten was sad and scared. The` for eight greedy tokens, matching the
Linux reference byte for byte. Generation took 110.04 seconds under QEMU TCG;
this is a single sample, not a performance benchmark. The browser adapter's
two-token request streamed ` The kitten`, with first text at 11.57 seconds.
Receipts are in
[the Mac evidence directory](../../../evidence/OMEGA-LOCAL-MODEL/macbook-20261106/).
The same firmware image passed invalid-frame and truncated-checkpoint refusal
checks on the Spark-hosted emulator. It is still an experiment, not a useful
speed replacement for the native ARM64 Linux inference path.

## Harness acceptance

The compiler is pinned by digest; build failures and mismatched pins must
refuse. A successful build alone does not pass acceptance. Boot the image,
require `LMREADY`, submit a fixed prompt, require `LMDONE`, and compare the
decoded generated bytes with the same checkpoint, seed and sampling settings
on the reference runner. Invalid frames must return `LMERR` without starting
inference; a following valid frame must still work. Corrupt or missing model
files must never produce `LMREADY`.

All model and firmware adapter implementation is Omega. QEMU and its firmware
provide the emulated machine. Test orchestration is outside the guest. The
separate experimental Mac llama UI adapter is host C++ and must not be described
as pure Omega or evidence of a native macOS Omega runtime.

## Build and boot

On Linux ARM64, the compiler is omega-mv's own `seed/out/omc`, checked against
`seed/out/omc.sha256` at the omega-mv root (aienux is folded into omega-mv as `kernel/`,
Drake 2026-11-17); before the fold it was the x86efi compiler pinned to
`3ad9f10f64309e7acf8a725082b28e23a2a4aeb07e98322fb4dc0fcd8fc93194`.
The training source needs `osampleloaded` in `native/omegallm/cli.om`.
Measured 2026-11-17 against aien-train b9bafc3c: both that old compiler and omega-mv's
omc `34d611ca…` stop at `omc: line 3866: error 4` on the composed unit, so this build does not
complete at that aien-train head with either compiler.

```sh
sh native/omega/allen/build-local-model.sh \
  /path/to/aien-train /fresh/output/BOOTX64.EFI
```

Install the image as `EFI/BOOT/BOOTX64.EFI` on a FAT disk. Put the checkpoint
at `ASTRA.CK` and tokenizer at `BPE.BIN` in its root. Attach the disk read-only
to QEMU with at least 2 GiB of guest RAM and one emulated CPU. No virtual NIC
is required. Serial console input/output carries the protocol below.

The selected inference-only checkpoint is the November 4 Astra weight edit,
SHA-256 `131f7e3f26f5494a9882d8107096d4209651978a5bf35eccb3f953203d1f07d6`.
The tokenizer SHA-256 is
`73a29baf97619a746a21232c403bf08af71a76e48b3b2cde6d64dab766083882`.
Check these externally before installing the disk. The model loader also
validates checkpoint shape, length and its format checksum. That checksum
detects corruption; it is not cryptographic authentication.

## Console protocol

After `LMREADY`, send `LM1 ID TOKENS TEMPMILLI SEED HEX_PROMPT` followed by CR.
ID and seed are unsigned 32-bit decimals; ID is nonzero. Tokens are 1 through
128, temperature is 0 through 2000 (0 means greedy). The prompt is 1 through
159 printable ASCII bytes, encoded as lowercase hexadecimal.

Responses are `LMSTART ID`, zero or more `LMDATA ID HEX_BYTES`, then
`LMDONE ID`. `LMERR ID CODE` refuses a request. The model is exclusive to one
request until completion. Firmware history holds only a printable preview;
it is not silently inserted into the next prompt. A host supplies any desired
conversation context explicitly.

The Mac launcher is **Aienux Omega.command**. Its separate llama UI endpoint is
`http://127.0.0.1:8099`, model **Omega-Astra-Aienux**. The host adapter pauses
the VM after completed requests and resumes it for the next request so firmware
polling does not occupy a CPU core while idle. Cancelling a generation stops
this private VM; reopening the launcher reloads the read-only model. The host
adapter and launcher are supplied by the aien-train UI experiment, not by a
Linux process in the firmware guest.

## Capability limit

This is the existing 15.8-million-parameter TinyStories model. The experiment
does not train a new model or establish improved math. It has failed the local
arithmetic and extraction probes documented by aien-train. Running it under
Aienux does not make it a replacement for a general small instruction model.
