Goal (Drake, 2026-10-20): "everything from up and down, hardware now and everything in the future". For the iMac that means every device on the board, the model run, and the iMac's place on the network of AienOS machines.

## 1. Plain-English summary

The iMac is the machine where our own software has run on real hardware the most. Two different programs run on it today, and they are easy to mix up:

1. **The C kernel** (`native/kernel/x86/`). Apple's firmware starts it from the iMac's own disk or from the network. It starts all four cores, reads both disks without writing, takes a USB keyboard, draws Aien's window and plays sound. A branch build of it also ran one small language model (15 million parameters) on the CPU on 2026-10-30; the model code is on `main`. Since 2026-10-24 this kernel is **frozen**: it takes bug fixes only, while Aienux is rewritten in Omega (`native/kernel/README.md`, line 3).
2. **Omega programs that run inside Apple's firmware** (UEFI applications), built by the Omega compiler's `x86efi` target. On 2026-11-14 one of them held a typed conversation on the iMac with our own Omega language model, using the same model files the Spark's own-model service loads, and its answer matched the Spark's answer byte for byte. Apple's firmware stays underneath these programs, so they are not the kernel.

Still missing for "everything": the Radeon GPU (nothing has run on it), Wi-Fi, Bluetooth, Thunderbolt, the SD reader, the camera, fan and temperature control, protection against devices writing anywhere in memory (VT-d: only the table reader exists), and a working chat link to the Spark from the Omega firmware app (its network does not come up; ledger L974 is open; the ledger records that on 2026-11-07 Drake asked for the remaining work to be handed to the Hive, and a later note says the remaining items "were paused by Drake").

OBSERVED in the repository:

- Pairwise secure transport `native/net/aienos_sec.{h,c}`, a signed and encrypted link between two machines that each know only the other's key: a three-message SIGMA-style handshake (X25519, Ed25519 identities, HKDF, AES-256-GCM-SIV). Each side accepts one peer key, "a pinned roster of one" (`aienos_sec.h:25`). Only TEST identities exist. Where it is proven: on `main` it is hosted code with host tests only (`native/net/README.md`: it "runs on TEST keys only"), and it is linked into no kernel image (`native/kernel/Makefile` links only `aienos_net.c` into the iMac and network boot images); its one real-hardware use is the Pi branch `pi5/net-398-wire`, not on `main`. Reliable channel `aienos_ctl.c`; UDP, IPv4, ARP and ICMP in `aienos_net.c`. No TCP, TLS, DNS or DHCP in `native/net`.
- The Omega firmware app carries its own HTTP and TLS units (`native/omega/allen/http.om`, `tls.om`, `tls-crypto.om`); they belong to that WIP app, not to a kernel network stack.
- Lab wire formats: unauthenticated report (lab image only), signed network boot (kernels checked with Ed25519 before start), and the courier that carries Aien's chat to the Spark over UDP, which is unencrypted and unauthenticated (`native/kernel/x86/courier_udp_x86.c:134`). Live kernel swap over the network is NOT BUILT (`docs/IMAC_GPU_BENCH.md`, Status). That document also says the GPU bench console is NOT TESTED on hardware; since then the 2026-10-30 branch build started it on the iMac, and it never answered (IM13).
- On `main`, the word "gateway" appears in no file under `native/net`, `docs/adr` or `docs/*.md` (other than these two maps), and no gateway code exists there. Ledger L690 (open) is a different thing: an Omega chat gateway for Aien, named in `docs/superpowers/specs/2026-10-23-allen-omega-platform-gates.md`.
- Not on `main` (OBSERVED in the repository): branch `feat/aienos-interplane-join` (head `5af5ac7d`, 2026-10-20, ledger L263, also L230 and L231 per its `docs/INTERPLANE_JOIN.md`) adds `native/net/aienos_ipj.[ch]`: an owner-signed roster of up to 15 machines (add, revoke, rotate), signed LAN beacons, rendezvous through a gateway that is a roster member with platform `hub`, and origin-signed messages relayed hop by hop, on top of `aienos_sec` with an optional responder roster hook. Where it is proven, per its commit messages and design document: hosted tests, and a 5-VM QEMU gate (`scripts/qemu_ck_interplane_test.sh`, PASS on 2026-10-20) in which Spark, Pi and Mac images join one roster, a partitioned Spark to Mac link is relayed through the Pi, and revoked and TEST identities are refused. QEMU only, never on hardware; the gateway rendezvous has hosted tests only ("no gateway runs on a real hub yet"). It adds feature code to the C kernel, written before the 2026-10-24 freeze, so like `pi5/net-398-wire` it is a reference design and QEMU evidence for the Omega transport (step 12), not a landing candidate.

Today's role (OBSERVED in the 2026-11-07 handoff `imac-boot-repair-20261107`): the iMac is a **leaf of the Spark**. The Spark answers its network boot, serves signed images, and runs the courier for Aien's chat. As of that handoff two faults stood between the iMac and a working chat: the Omega firmware app's network never came up (L974, open; see section 3 for its recorded pause), and the courier's model backend pointed at a port with no listener (L975). This map does not re-check either.

The MacBook today is the operator's machine in this picture: it writes the iMac's boot sticks and reads them back for the byte comparison (handoff `imac-x86-boot-20261113`), and it hosted the emulated local-model run (IM-M3). It runs macOS (the stick guide drives it from Terminal) and is not always on, so it is not a gateway candidate (INFERRED, high).

Role to aim for (INFERRED, high): Aien's screen and a small local model on its own; a **peer of the Spark** for big-model work once identities are real and the roster holds more than one peer. It does not need to be a gateway, relay or time source. Owner-issued machine identities are written in seeded Omega in `native/omega/netid/` (ledger L231: the owner root on the owner YubiKey, PIV slot 9c, `docs/OWNER_KEY_CEREMONY.md`, issues each machine's Ed25519 credential; TEST credentials and other roots are refused; SIGMA handshake over TCP). It is not on `main`: it is held only under the Radicle-era ref `refs/heads/patches/0de8f71b00c8df8f79d3515beeabc7c95af277a4` (head `b821a0dd`, 2026-11-09), which is history; landing it needs a fresh review and the gates through the current route. Where it is proven, per its README: IMPLEMENTED and EXERCISED on Linux hosts only (`tests/run.sh`, and `tests/twomachine.sh` between the Spark and the Pi 5 hub), with a stand-in owner key generated for the test; nothing has run on Aienux. Its handshake runs over the host's TCP sockets, and `native/net` has no TCP, so landing netid does not by itself give the iMac a multi-peer roster. Its README lists wiring into `native/net/aienos_sec.c` as a next step, but that file is in no kernel image on `main`, and putting it into the frozen C kernel would be new feature work there. What the native side needs is a signed machine-to-machine transport written in seeded Omega, and none exists yet: aienux `native/omega` holds only the firmware app and platform units, and omega-mv `main` has the primitives (for example `om/tls/gcmsiv.om`) but no such transport (NOT BUILT; whether it runs over native TCP in Omega or over UDP is a design decision not yet made).

Joining the tailnet: a native node needs WireGuard and Tailscale's control protocol over TCP and TLS; neither exists in `native/net`. The near-term route is the Linux hub advertising the home network so the other machines reach the iMac at its LAN address (INFERRED, medium). Until the Omega transport above exists, the iMac's traffic on that route is the unencrypted courier and the unauthenticated lab report: lab traffic, not the signed network role.

## 6. Ordered path

Notation: **[H]** host or QEMU only; **[A]** needs the iMac with a stick or network boot and a power-on; **[O]** Drake only; **[C]** needs the GPU chip. Because the C kernel is frozen, new device work is written in Omega; fixes to the C kernel are allowed and come first where they touch safety.

1. [H] Fix L1281 F1 to F7, F9 and F10 in the C kernel (bug fixes are allowed while frozen): stop every device's DMA before memory is handed on, check the xHCI halt result. F8 (no DMA confinement) is new work, answered by step 7. Confirm and fix the compute queue selection (IM14), and re-run `scripts/gpu_bench/check_regs.sh`.
2. [H] Land what already ran on the iMac: aien-train `imac/x86efi-ask` with its evidence folder, after a fresh review.
3. [H] Move the firmware app off the omega-mv pin `b8bd1d03` (it sits on `fix/imac-net-L974-snp`, not on omega-mv `main`, so the app on aienux `main` cannot be rebuilt from the newest Omega build). Land what the app needs from that pin onto omega-mv `main`, or retarget the app to the newest build, and repin `native/omega/allen/README.md`. Then [O] confirm with Drake that the recorded L974 pause is lifted, [H][A] bring up the firmware app's network and give the courier a real own-model backend, and record one chat turn from the iMac to the Spark. That chat turn travels over the unencrypted courier: it is unauthenticated lab traffic, like the lab report, and is not the signed network role of section 5.
