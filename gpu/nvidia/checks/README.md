# gpu/nvidia/checks: Omega checks for part of CUDApp tests and tools

CUDApp keeps its tests and tools in C, Python and shell (`tests/`, `tools/`). This directory is one slice of porting them to Omega, not the whole port: the checks listed in `checks.tsv` with the tables of expected values they read, their gate, and an inventory that lists every file of `tests/` and `tools/` with its status, so what is still open is counted in `INVENTORY.tsv` rather than claimed done.

## What is here

| File | What it is |
|---|---|
| `INVENTORY.tsv` | One row for every file of CUDApp `tests/` and `tools/` that is not Omega, with its status. Generated by `inventory.om`; do not edit. The gate fails when it no longer says what `ports.tsv` says. |
| `ports.tsv` | The decision for each such file: `ported`, `retired` or `blocked`, with the reason. Written by hand; this is the only human input. |
| `inventory.om` | The program that writes `INVENTORY.tsv`. |

## How a check works

A check is one program made of parts joined in order: the `gpu/` Omega units under test, then `lib.om`, then the check itself. `lib.om` reads the table one line at a time and calls the check's `crow` for each case. A case is a line that is neither empty nor starts with `#`. The program prints one `FAIL line N:` line per failed case and ends with `NAME PASS rows=N`, exit 0, or `NAME FAIL rows=N failed=F`, exit 1. A table with no case fails. A field it cannot read gives exit 2.

The tables hold the old implementation's own answers, written by an outside C driver (an oracle) compiled against the old CUDApp sources and run outside this repository. The oracles are not committed here: they are C. Where they are kept, their sha256 and how to rebuild them are under [Oracles](#oracles). The header lines of each table name its oracle and the CUDApp commit.

Some units are function-mode units: they export their functions with `export fn` and have no `main`. The compiler refuses a program that has both `export fn` and a `main`. So, when the gate joins the parts, it turns any line that starts `export fn ` into `fn `. Nothing else in the unit changes, and the function bodies are tested exactly as committed.

The program's dialect is set by its first unit: `om2` must be the program's first line that is not a note. An OM-1 unit cannot always be forced into OM-2, because OM-2 reserves words some OM-1 units use as names (`gpu/nvidia/om/gdn/admit.om` defines `fn layout`). This is why `lib.om` is OM-1 and the text-taking helpers live in `lib-om2.om`.

## The gate

```
tests/gates/run.sh gpu-checks
```

The gate first checks that `seed/out/omc` matches `seed/out/omc.sha256`. Then, for each row of `checks.tsv`, it:

1. joins the parts;
2. compiles them twice and requires identical bytes and empty stderr;
3. runs the check on its table and requires exit 0;
4. runs it again on a copy of the table with one byte changed, and requires exit 1 (the table control);
5. for each row of `mutants.tsv` that names this check, joins the parts again with the line of the named part that equals FROM replaced by TO, requires that to compile, and requires the check built from it to exit 1 on the true table (a source-mutant control). FROM is matched after the `export fn ` strip, and it must equal exactly one line of the part. A FROM that matches no line or more than one line, a mutant that does not compile, and a mutant the check does not notice each fail the gate.
   A row may carry two more fields, EXIT (decimal, 1 to 255) and KTABLE, for a known difference that ends the check, such as a trap. Then the check as built must exit EXIT on KTABLE, and the check built with TO (the repair) must exit 0 on KTABLE, so KTABLE holds the pending C's answers and the repaired unit gives each of them. If the unit changes so it no longer exits EXIT, or the recorded answers stop being what the repair gives, the row fails. Such a row is one control.

A wrong-compiler control runs once: a compiler one byte longer must fail the digest check.

Then it checks the inventory: each row of `ports.tsv` must be the status and detail of its path's row in `INVENTORY.tsv`, every other row of `INVENTORY.tsv` must be `open`, the counts in its last line (`files`, `ported`, `retired`, `blocked`, `open`) must be the counts of its rows, and every `om_ref` and `same_stem` cell that is not `-` must name a `.om` file under `gpu/` that exists in this tree. A failure here means `INVENTORY.tsv` was not regenerated after `ports.tsv` or the `gpu/` tree changed. The gate does not check the CUDApp side of the inventory (paths, kinds, sizes); that needs a CUDApp checkout, see below.

The summary must read `OMEGA-GPU-CHECKS PASS checks=N controls=C caught=C hardware=NOT_RUN`. N is the number of rows of `checks.tsv` and C = N + (rows of `mutants.tsv`) + 1: one table control per check, one control per mutant, and the wrong compiler. `run.sh` computes both from the two files. The gate checks nothing more than the above. Nothing here opens a device. Any hardware tier of an old test is recorded as NOT_RUN in `ports.tsv`.

The gate reads its files into memory that grows to fit them, and hashes files of any size; it has no fixed size for them. If the host refuses the memory, the check fails with a message saying so. Paths are held in buffers of Linux PATH_MAX bytes (the host words that take a path cannot take growing memory); a path that does not fit, a check name that with its scratch suffix does not fit Linux NAME_MAX, or a SCRATCH directory too long for both is refused by name (FAIL, or exit 2 for SCRATCH), never cut short.

## Regenerating INVENTORY.tsv

`INVENTORY.tsv` depends on the CUDApp files, which are not in this repository, so the gate does not rebuild it; it only checks that it agrees with `ports.tsv`. Regenerate it after every change to `ports.tsv`, from a CUDApp checkout at the commit named in its second line:

```
seed/out/omc < gpu/nvidia/checks/inventory.om > inventory && chmod 700 inventory
git -C CUDApp ls-files tests tools > list.txt
git -C omega-mv ls-tree -r --name-only HEAD -- gpu > gpulist.txt
cd CUDApp && ../inventory ../list.txt ../gpulist.txt ../omega-mv/gpu/nvidia/checks/ports.tsv "LABEL" > ../omega-mv/gpu/nvidia/checks/INVENTORY.tsv
```

LABEL is the inputs line, the second line of `INVENTORY.tsv`: it names the CUDApp commit of the checkout and the omega-mv commit whose `gpu/` list was read, so put the commits you actually used there. `inventory` exits 1 in two cases: a `ports.tsv` row names no CUDApp path, or a path appears twice. It exits 2 on a malformed row, on a path that does not fit Linux PATH_MAX, or when it cannot read an input or the host refuses the memory; it reads inputs of any size into memory that grows to fit them.

What is still open, by tier and kind, is the line `# open by tier/kind:` just above the counts at the end of `INVENTORY.tsv`: `inventory.om` writes one `TIER/KIND=COUNT` per tier and file extension of the `open` rows (`none` for a file without one), in the order each first appears. Read the figures there; this README does not repeat them.

## Why files are retired

A file is `retired` only when no behaviour of it is left unchecked: it is not a test or tool (prose, session metadata, recorded evidence), or the job it did no longer exists once CUDApp is folded into omega-mv. A test whose behaviour no Omega check covers is never retired; it stays `open` or is `blocked`. Every retired row of `ports.tsv` gives one of these reasons; the rows themselves are the list of files.

| Reason (DETAIL begins) | Why it is safe |
|---|---|
| `agent breadcrumb (.crumb)` | Session metadata of the CUDApp lanes. Not a test, a tool or an input to one; nothing reads it. |
| `recorded evidence of a past run` | A receipt or its log. No `.om`, `.c`, `.h`, `.py`, `.sh`, `.gate` or make file of CUDApp names it, so no test or tool reads it. It records a past run; it checks nothing. |
| `prose (Markdown)` | Not a test and not an input: nothing runs or reads it. It stays readable in CUDApp history, and each Omega port documents itself in its own README. |
| `tools/extract drift check` | `drift.sh` failed when Omega's copy of a GPU file moved away from CUDApp after the cutover; `test-drift.sh` tests only `drift.sh`, and `drift-baseline.tsv` is its input. With one copy of each file left there is nothing to drift. |
| `tools/extract history cut` | Scripts, path lists, maps and outputs of the one-time cut of the CUDA++ history out of the Omega and physics repositories into CUDApp. The cut is not repeated, and no test or tool reads these files. |

Not retired from `tools/extract`: `audit-scan.sh`, its rule files `rules-secrets.txt` and `rules-private.txt`, and its self-tests `audit-selftest.sh` and `audit-error-selftest.sh`. They scan every object of a repository's history for secrets, private data and binaries; that job still applies to omega-mv, which has no Omega replacement for it, so they stay `open`.
